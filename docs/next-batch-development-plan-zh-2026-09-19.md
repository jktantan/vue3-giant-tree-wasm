# 下一批次开发计划：远程树加载与产品边界

## 背景与定位修正

`VueGiantTree` 同时适用于小型权限树和大型本地树。只要业务需要当前已支持的复选联动、搜索、展开/折叠、字段映射、禁用节点或节点插槽，几百或几千节点并不是选择其他树组件的理由；其接入方式已经是普通的 Vue 组件 API。

小型树场景下，成熟 UI 库的树组件只有在业务需要 `VueGiantTree` 尚未提供的能力时，才可能拥有更低的总拥有成本，例如远程子节点加载、拖拽、动态行高、完整的树键盘导航或 SSR。性能本身不是避免使用 `VueGiantTree` 的理由。

## 当前 `chunkedBuild` 的能力边界

`chunkedBuild` 是可选的本地输入桥接优化，不是远程懒加载：

1. 调用方在组件挂载前提供完整的 `tree` 数组。
2. 组件按 `buildBatchSize` 切分数组，并通过 `pushNeighborNodesUtf8` 写入每一批。
3. 批次之间让出主线程；最后一批结束后调用一次 `popNeighbor`，构建 MPTT 并渲染树。

WASM 层在 `popNeighbor` 前会将批次累积在临时邻接表缓冲区中。因此它不能渲染提前到达的批次，不能请求某个节点的子节点，也不能把新获取的一页数据合并到已构建的树中。组件层目前同样没有公共 append API 或 `tree` 变更协调逻辑。

文档与发布说明必须将该功能称为“本地大树分批构建”，不得称为远程加载、流式渲染或懒加载。

## 目标

在不改变现有静态树 API 与行为的前提下，增加可选的远程树模式：按需获取并增量合并一个节点的直接子节点，且不重建整棵树。

首个版本定位为“远程子节点加载树”，不是任意服务端语料的分页搜索树。搜索语义必须明确，不能暗示客户端模糊搜索能够覆盖尚未加载的节点。

## 建议的公开 API

采用回调式 API，将请求实现、鉴权、分页与应用级缓存保留在业务方：

```ts
type LoadChildren = (context: {
  node: TreeNodeData | null // null 表示配置的根节点
  signal: AbortSignal
}) => Promise<TreeInputItem[]>

interface RemoteTreeOptions {
  loadChildren: LoadChildren
  hasChildren?: (node: TreeInputItem) => boolean
  cachePolicy?: 'component' | 'none'
}
```

- 配置 `remoteTree` 后，组件挂载时请求根节点。
- 展开未加载节点时调用一次 `loadChildren`；默认情况下再次展开复用组件缓存。
- 请求失败时暴露错误状态，并允许显式重试。
- 默认折叠节点不取消请求；组件卸载或替换树会话时必须取消未完成请求。
- 首版 API 必须保持单一事实来源：远程行数据写入组件内部的规范化存储，不直接修改调用方的 `tree` prop。

实现前需要确认 `remoteTree` 应作为独立 prop，还是以 headless controller/composable 形式提供。不得将原始 `pushNeighborNodesUtf8` 暴露为组件 API：它是高效的构建桥接原语，不是稳定的 UI 合约。

## 数据与状态语义

每个节点都需要独立的子节点加载状态：

```text
unknown -> loading -> loaded
                  -> error
```

补充要求：

- 必须区分“未知”与“已加载但没有子节点”，否则无法正确渲染叶子节点。
- 子节点到达后保留既有选中状态和折叠状态。
- 明确祖先已勾选或已禁用时，后到达子节点的勾选/禁用传播语义。
- 对重复 ID 与孤儿节点进行确定性拒绝，并提供面向开发者的错误路径。
- 未显式引入排序器前，保持服务端返回的兄弟节点顺序。
- 客户端模糊搜索仅检索已加载节点。未来服务端搜索 API 必须返回祖先上下文，不能将不完整结果静默混入现有本地搜索视图。

## 实施阶段

### 阶段 1：架构与兼容性

- 明确 `remoteTree` API、事件名、加载/错误插槽合约与缓存失效规则。
- 在 README 中增加能力矩阵，区分静态本地树、`chunkedBuild`、远程子节点和服务端搜索。
- 验证静态 `tree` 的既有行为不变，远程模式不得成为默认模式。

验收：完成 API 评审，覆盖请求取消、重复 ID、空子节点、重试、已选祖先和未加载搜索等情形。

### 阶段 2：增量核心变更

- 在 WASM 中新增操作：向既有父节点插入经校验的直接子节点，并更新 MPTT 边界、ID 索引、紧凑布局、可见索引和选中聚合状态。
- 禁止以 `tmpTree + popNeighbor` 或整树重建的方式实现插入。
- 增加批量插入操作，以保持较低的 JS/WASM 跨边界调用次数。

验收：使用随机差分测试，将增量插入结果与全量重新构建进行对比，校验排序、MPTT 边界、可见性、选中状态、禁用传播和各勾选输出模式。

### 阶段 3：Vue 远程控制层

- 实现根加载、展开触发子加载、并发请求去重、失败/重试、卸载中止与组件缓存。
- 通过插槽或明确的行状态呈现加载和错误，默认 UI 保持简洁。
- 只刷新受影响的虚拟行；插入位置不在视口前方时保持滚动位置。

验收：浏览器测试覆盖根加载、子加载、重复展开、并发展开、失败/重试、请求中卸载，以及子节点到达前后的选中行为。

### 阶段 4：性能与发布门禁

- 针对累计 1k、10k、100k 节点与代表性分支宽度，压测远程追加。
- 测量请求完成到可见行绘制、受影响展开操作 P95、堆内存、WASM 内存与 JS/WASM 桥接量。
- 原有静态树的 Node、组件与浏览器门禁必须保持不变。
- 发布从静态树和 `chunkedBuild` 迁移到远程模式的说明，并明确客户端搜索局限。

验收：静态路径不超过约定的回归阈值；远程追加不重建整树；现有测试和新增远程测试全部通过。

## 本批次非目标

- 服务端全局模糊搜索。
- 拖拽或任意节点移动。
- 动态行高虚拟化。
- SSR 支持和完整的 WAI-ARIA 树键盘导航。
- 替换现有 `chunkedBuild` 路径；对于已经完整到达的大型本地数组，它仍是优先路径。

## 完成后的产品表述

应明确支持两种场景：

1. **静态本地树：** 使用 `tree`；当完整本地数组很大且需要保持主线程响应时，启用 `chunkedBuild`。
2. **远程子节点加载树：** 使用 `remoteTree`；按需加载子节点，并在不重建整树的前提下增量合并。

不得宣称任一模式在所有情况下都比成熟 UI 库的树组件更快；差异化在于“大树能力”与“所需交互语义”的组合。
